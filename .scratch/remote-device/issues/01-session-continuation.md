# 01: 会话续接真正执行

**What to build:** 在投射端（A）打开被投射设备（B）的一个会话，直接在提交框继续对话 —— 执行发生在 B，且**B 的会话库里真的新增消息**，B 本机打开同一会话也能看到这些内容。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

这是整个方案能否成立的判决点：若续接无法真正执行，则"投射端可操作对方会话"这一核心诉求不成立，需重新评估方案。

- [ ] 在 A 上对 B 的一个会话发起续接（激活会话 + 发送一条输入）
- [ ] B 的会话库中该会话出现新的用户消息与助手回复（能被独立观察，不依赖发起端的返回值）
- [ ] 该会话的执行确实发生在 B（可由 B 的运行时或库状态佐证）
- [ ] 测试只操作自己新建的一次性测试会话，结束后清理；不得触碰用户既有会话
- [ ] 记录未打通时的具体失败环节（哪一步骤之后数据没有落地）

**已知证据（起点，不是结论）**：`resumeTask` + `subscribeConversationV4` + `sendPrompt` 调用链全部被对端接受、无报错，但 B 的会话库没有新增消息、会话状态未变化。结论是"调用被接受 ≠ 已执行"，链路上有未打通环节。真实 UI 链路可能含额外的会话激活/绑定步骤。
